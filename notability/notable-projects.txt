# Ravn notability set — projects a contribution to is worth asserting.
#
# set: ravn-notable/2026-08
#
# ❗THE REPORTER DOES NOT DECIDE WHAT IS NOTABLE. This list does, and it ships
# INSIDE ravn-actions at the same commit the collector is pinned to — so the
# attested `job_workflow_sha` covers the list as well as the code. A fork with a
# padded list produces a different SHA and fails verification, exactly as a
# modified collector does.
#
# That is also why this is not fetched at runtime. A list pulled from the network
# mid-run is a list nobody attested, and "which version of the list ran" would
# become unanswerable at precisely the moment it mattered.
#
# GOVERNANCE, same shape as approved-workflow-shas.txt:
#   • one `owner/repo` per line, lowercase, no trailing slash;
#   • `#` comments and blank lines ignored;
#   • additions are a PR to this file, which forces a new approved SHA — a
#     deliberate speed bump, because this file decides what "well-known" means.
#
# ❗Absence from this list is NOT a judgement about a project. It means Ravn has
# not curated it yet. A reporter can nominate any repository via `nominate_repos`
# in their collection config; it is then carried as their assertion rather than as a
# notable-project claim, and shown that way.
#
# Selection principle: broadly depended upon, or squarely in the security domain
# — the two cases where "this person has contributed here" tells a PSIRT team
# something useful about who is filing their report.
